# 資産マップ（どのファイルが何を担当するか）

サイト個別の調整をAIへ依頼するとき、**どのファイルを渡せば足りるか**が
分かるようにするための一覧です。渡す資産が少ないほど回答は正確になります。

---

## 1. 目的別「渡す最小セット」

| やりたいこと | 渡すファイル | 補足 |
|---|---|---|
| 既存サイトの本文が取れない／広告が混ざる | `config/sites/<id>.json` ＋ 対象記事ページのHTML（またはURL） | セレクタの修正だけで済む。Pythonは不要 |
| 新しいサイトを足す（RSSあり） | `config/sites/_template_html.json` ＋ `docs/02_サイト設定リファレンス.md` ＋ 記事ページのHTML | 既存の似たサイトの設定も一緒に渡すと早い |
| 新しいサイトを足す（RSSなし・一覧HTMLから拾う） | 上記＋**一覧ページのHTML** | `listing.type: "html"` と `linkSelector` を決めるのに一覧HTMLが必須 |
| 抽出の仕組み自体を直す（セレクタでは無理な構造） | `collector/extractor.py` ＋ `config/sites/<id>.json` ＋ 記事HTML | 影響が全サイトに及ぶので変更は最小限に |
| 一覧の拾い方を直す（ページ送り・API利用など） | `collector/listing.py` ＋ 対象の `config/sites/<id>.json` | |
| 「更新のある記事だけ取る」判定を変える | `collector/main.py` ＋ `collector/state.py` | 判定は `main.py` の `need = ...` に集約してある |
| 配信JSONの項目を増やす | `collector/publisher.py` ＋ `docs/03_配信JSON仕様.md` ＋ アプリ側 `NewsHubModels.kt` | **アプリ側と同時に直す**。片方だけでは反映されない |
| 実行時刻・回数を変える | `.github/workflows/collect.yml` | UTC指定 |
| 通信量・件数の上限を変える | `config/global.json` | |

## 2. ファイル別の責務

### 設定（触る頻度：高）

| ファイル | 責務 | 直すと影響する範囲 |
|---|---|---|
| `config/sites/<id>.json` | 1サイトの取得元URL・件数・本文/画像/日付のセレクタ・除外・打ち切り語 | そのサイトだけ |
| `config/global.json` | 共通の上限（件数・本文文字数・保持日数）、待ち時間、リトライ | 全サイト |

### 収集の処理（触る頻度：低）

| ファイル | 責務 | 主要な関数 |
|---|---|---|
| `collector/main.py` | 全体の流れ。**「取りに行くかどうか」の判定** | `run_site()` の `need` 判定 |
| `collector/listing.py` | 一覧の取得と解析（RSS2.0/RDF/Atom、HTML一覧） | `from_feed()` `from_html()` `collect()` |
| `collector/extractor.py` | 記事ページから見出し・本文・画像・日付を抜く | `extract()` `_densest()`（汎用推定） |
| `collector/fetcher.py` | HTTP（条件付きGET・リトライ・待ち時間） | `Fetcher.get()` |
| `collector/state.py` | 前回の記憶（`state/<id>.json`）の読み書き | `SiteState` |
| `collector/publisher.py` | 配信JSONの組み立てと書き出し（rev計算） | `site_payload()` `write_site()` `write_index()` |
| `collector/normalize.py` | URL正規化・ハッシュ・文字整形 | `normalize_url()` |
| `collector/config.py` | 設定の読み込みと検証 | `load_sites()` `validate()` |
| `collector/selftest.py` | 通信しない机上検証 | `main()` `pipeline_test()` |

### 運用

| ファイル | 責務 |
|---|---|
| `.github/workflows/collect.yml` | 1日3回の実行、机上検証、収集、`public/`と`state/`のコミット |
| `.github/workflows/pages.yml` | GitHub Pagesで配信する場合のみ（任意・不要なら削除） |
| `tools/local_run.bat` / `.ps1` | 手元のWindowsで試験実行 |

### 自動生成（手で編集しない）

| ファイル | 中身 |
|---|---|
| `public/index.json` | サイト一覧＋サイトごとの版(rev) |
| `public/sites/<id>.json` | そのサイトの記事（本文・画像URL入り） |
| `state/<id>.json` | 前回の記憶（URL・ハッシュ・ETag・本文） |

## 3. アプリ側（TogoKanri）との対応

| 配信側 | アプリ側 | 揃えるべき決めごと |
|---|---|---|
| `publisher.py` の出力形 | `NewsHubModels.kt` | 項目名。増やすときは両方 |
| `normalize.py: normalize_url()` | `NewsRepository.normalizeUrl()` | **同じ規則**。ずれると記事が二重に並ぶ |
| `bodyBlocks[].kind` の値 | `HtmlText.Kind`（H/P/LI/QUOTE） | 未知の値はPとして描画される |
| `index.json` の `sites[].rev` | `NewsHubConfig.revs` | 差分取得の要。値の作り方を変えたら端末側の記憶を消す |
| `category` | `NewsCategory`（GENERAL/TECH/GAME/STOCK/MATOME） | この5値以外はGENERAL扱い |
| `allowFullText` | `NewsSource.allowFullText` | falseなら本文を配信せず端末も保持しない |

## 4. 変更してはいけないこと（互換の境界）

- `public/index.json` の `sites[].id` は端末の取得元ID（`hub_<id>`）の元になります。
  **IDを変えるとアプリ側では別サイト扱い**になり、既読が引き継がれません。
- `state/` を消すと「全記事が新規」として作り直され、初回と同じだけ通信します。
  取り直したい時だけ意図して消してください。
- `rev` の作り方（`publisher.py` の `sha(...)`）を変えると全サイトが更新扱いになります。
  変更した回は通信が増える前提で行ってください。
