# トラブルシュート

---

## GitHub Actions 側

| 症状 | 原因 | 対処 |
|---|---|---|
| ワークフローが一覧に出ない | `.github/workflows/collect.yml` が上がっていない | Uploadで `.github` が除外されたケースが多い。再アップロード |
| 実行が赤く終わる（push失敗） | Actions の権限が読み取り専用 | Settings → Actions → General → Workflow permissions を **Read and write** |
| 実行が赤く終わる（selftest FAIL） | 設定JSONの書式ミス | ログのNG行を見て `config/sites/*.json` を直す。手元で `python -m collector.selftest` |
| 定時に動かない | cronがUTC／リポジトリが60日以上無操作 | 時刻はUTC。publicリポジトリは長期間コミットが無いとスケジュールが停止するので、Actionsから手動実行すると再開する |
| 実行はされるがコミットが無い | 更新が1件も無かった | 正常。`更新なし。コミットしません。` とログに出る |
| 実行が遅い／途中で終わる | 初回で本文取得が多い | `global.json` の `maxNewArticlesPerRun` を下げ、数回の実行で揃える運用にする |
| 特定サイトだけ失敗が続く | サイト構造の変更・アクセス制限 | ログの「記事取得失敗」を確認。`enabled: false` で一旦止め、`docs/04` の手順で調整 |

## 配信JSON の中身

| 症状 | 原因 | 対処 |
|---|---|---|
| `bodyBlocks` が空ばかり | セレクタが当たっていない／`allowFullText: false` | `docs/02` の「よくある症状」を参照。falseは仕様（本文を配信しない） |
| 記事が増えない | 一覧が304のまま／`maxItems` が小さい | 一覧URLが正しいか、`maxItems` を確認 |
| 古い記事が消えない | `keepDays` が大きい | `global.json` の `keepDays`（既定14日）を調整 |
| 全サイトが毎回更新扱いになる | `rev` の作り方を変えた | 一度は全件更新になる。その後は落ち着く |

## アプリ側（TogoKanri）

| 症状 | 原因 | 対処 |
|---|---|---|
| 「今すぐ取得」でHTTP 404 | 配信URLが違う | `public/index.json` の Raw URL を貼り直す。ブランチ名（main）とフォルダ（public）を確認 |
| 「index.json を読めません」 | URLがHTMLページを指している | GitHubの通常ページではなく **Raw** のURLを使う |
| 取り込めているが記事が出ない | タブ条件に合っていない | タブの対象カテゴリ／除外キーワードを確認。配信側の `category` がタブと合っているか |
| 同じ記事がRSSと配信JSONで二重 | URL正規化の規則がずれている | `normalize.py` と `NewsRepository.normalizeUrl` を同じ規則に戻す |
| 更新が反映されない | 版の記憶が残っている | 設定の「版の記憶を消す」を押してから取得（全サイト取り直し） |
| 通信量が気になる | 画像・本文を全部入れている | 「画像も取り込む」をOFF、`1サイトあたりの取込件数` を下げる |
| RSSでも同じサイトを取ってしまう | 取得元にRSS版が残っている | 取得元一覧でRSS版を無効化する（配信版は `hub_` で始まる） |

## 手元での確認コマンド

```
python -m collector.selftest                      # 通信しない（設定・抽出・差分判定）
python -m collector.main --validate               # 設定の検証のみ
python -m collector.main --site <id> --limit 3 --dry-run   # 1サイトだけ試す
```
